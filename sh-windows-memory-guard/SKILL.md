# sh-windows-memory-guard — Windows 内存过载防护与虚拟内存调优

针对“多开开发工具(Zed/VSCode/Cursor)、大模型、Chrome 几十个标签导致内存飙升（90%+），担忧电脑超内存死机或蓝屏”。
核心原则：**用高速 NVMe SSD 虚拟内存构筑兜底防线，以平滑的后台 I/O 换页替代系统死机与 OOM 闪退；配合标签休眠彻底治愈浏览器内存黑洞**。

## 五条核心认知（先读这个）

1. **物理内存占满 90%+ 绝不会直接死机或蓝屏**。Windows 拥有成熟的分页机制，物理内存吃满后系统会自动将冷数据转移至硬盘的 `pagefile.sys`。
2. **只有“提交配额（Commit Limit）”耗尽才会发生应用闪退**。物理内存 + 虚拟内存全部耗尽时，系统才会触发 OOM 保护机制强杀进程。只要手动将虚拟内存底座锁定在 32GB~48GB（总提交配额突破 55GB~70GB+），即可彻底杜绝死机与闪退。
3. **“卡顿”是安全代价，非系统故障**。当数据在物理内存和固态硬盘之间置换时，SSD 相对物理内存的延迟差距会导致后台切前台时有 1~2 秒唤醒延迟。这是“用慢换不崩”的正常表现。
4. **虚拟内存置换不产生 CPU 高温，风扇狂转为伴生现象**。虚拟内存换页是存储 I/O，不引起 CPU 发热；开机 40 分钟内风扇狂转源于软件重启后的集中初始化（IDE 索引重建、杀毒扫描、AMD CPU 激进睿频），属正常暂态。
5. **Chrome 等现代浏览器是物理内存的第一膨胀源**。由于多进程沙箱架构、会话恢复全量预加载及流媒体“免死金牌”，浏览器极易在启动时霸占 5GB~8GB+。必须配合精准标签休眠（Discard）剥离冷内存。

## 工作流

1. 只读体检（`memory-triage.ps1` 输出物理内存、提交配额、页面文件大小及峰值使用）
2. 压力判型（区分是正常高负载换页、虚拟内存不足，还是浏览器/进程内存暴涨）
3. 底座防护加固（通过 `sysdm.cpl` 手动锁定 32GB~48GB 护城河）
4. 应用层内存治理（Chrome 原生性能模式 + Auto Tab Discard 黄金策略）
5. 调优决策与答疑（调优上限边界、系统默认妥协原因、Discard 底层机制）
6. 验证与汇报

## Step 1 只读体检

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File <skill目录>\scripts\memory-triage.ps1
```

输出项及诊断重点：
- **物理内存占用率**：超过 85% 触发冷页置换（只要可用物理内存留有 2G~4G 缓冲即属健康）；
- **已提交 (Committed) vs 总配额 (Commit Limit)**：若 Committed 超过 Commit Limit 的 85%，说明提交池亟需扩容；
- **页面文件峰值 (Pagefile PeakUsage)**：大于 1GB 说明系统正平稳利用虚拟内存安全代偿，非系统故障。

## Step 2 压力判型表

| 现象与指标 | 关键数据特征 | 诊断判型 | 处置方向 |
|---|---|---|---|
| 物理内存 80%~90%，Commit 裕量 >20GB | 页面文件使用 >1GB，SSD 空间充足 | 黄金代偿态 | 系统正通过虚拟内存平稳兜底，绝不会死机；无需恐慌，放心使用 |
| 物理内存 >90%，Commit 裕量 <8GB | 提交已占用 >85% | 接近 OOM 警戒线 | **立即扩容虚拟内存**，防止下一次突发申请导致应用闪退 |
| Chrome 重启即飙升 5GB+，多开视频/长连接 | Chrome 独占 5G~8G，多进程且内存不释放 | 浏览器会话与流媒体霸占 | **按 Step 3.2 治理**：关闭预加载，配置 Auto Tab Discard 强制休眠 |

| 刚开机软件齐开，风扇狂转 | CPU 瞬时 30%~50%，磁盘 I/O 平稳 | 启动期密集计算 | Zed 正在建代码索引、杀毒全盘扫描、AMD 睿频温升；静候 5 分钟自动平息 |

## Step 3 处置与调优 SOP

### 3.1 虚拟内存加固配置（系统级防死机核心）

让系统不再受制于动态分配的瞬时延迟，直接开辟大容量安全气囊：

1. 按 `Win + R` 键，输入 `sysdm.cpl` 回车，打开“系统属性”。
2. 点击 **“高级”** 标签页 ➔ “性能”分组框内的 **“设置(S)...”**。
3. 在性能选项中，再次点击 **“高级”** 标签页 ➔ “虚拟内存”分组框内的 **“更改(C)...”**。
4. **取消勾选**最上方的 *“自动管理所有驱动器的分页文件大小”*。
5. 选中剩余空间充足的高速 NVMe SSD 盘符（首选系统 C 盘，空闲建议 >40GB）：
   - 单选 **“自定义大小”**：
   - **初始大小 (MB)**：填写 `32768`（即 32 GB）
   - **最大值 (MB)**：填写 `49152`（即 48 GB）
6. ⚠️ **关键操作**：**必须点击右侧的【设置(S)】按钮**，确认上方列表出现数值变更！
7. 点击【确定】依次关闭窗口，根据系统提示**重启电脑**生效。

### 3.2 Chrome 内存黑洞治理与 Auto Tab Discard 调优（应用级节流核心）

每次重启 Chrome 拉到 5GB+ 的病根：**会话恢复全量加载 DOM + 预加载机制 + 抖音等流媒体拥护“免死金牌”不主动释放**。

#### A. Chrome 原生设置调优
1. **开启省内存模式**：
   - 访问 `chrome://settings/performance`；
   - 开启【省内存模式（Memory Saver）】，并将休眠策略档位选为 **【最大限度（Maximum）】**。
2. **关闭预加载网页**：
   - 访问 `chrome://settings/performance` 或在隐私设置中搜索“预加载”；
   - 将【预加载网页（Preload pages）】设为 **【关闭（No preloading）】**，禁止后台预取页面吃带宽和内存。

#### B. 安装并调优 Auto Tab Discard 扩展
Chrome 原生机制对“正在播放音频/视频、含长连接（如大模型问答）、有表单输入”的标签坚决不休眠（免死金牌）。必须借助 `Auto Tab Discard` 强制执行底层 `chrome.tabs.discard`：

1. **安装**：Chrome 应用商店搜索并安装 `Auto Tab Discard`。
2. **黄金配置项（打开插件选项页逐项配置）**：
   - ✅ **勾选【启动时休眠所有非固定标签页（Discard all inactive tabs on startup）】**（核心：彻底终结启动即吃 5G 的偷跑行为）；
   - ✅ **勾选【启动时休眠全部未加载标签页（Discard unloaded tabs on startup）】**；
   - ✅ **勾选【记录 YouTube 播放进度（Remember YouTube position）】**（休眠后不丢视频进度）；
   - ❌ **取消勾选【打开临时空白页面（Discarded tab opens a temporary blank page）】**（避免切换标签时突兀白屏，保持平滑原位激活）；
   - 💡 **免死金牌裁决**：当开启多个抖音/B 站后台标签吃满数 GB 时，直接点击插件图标 ➔ 选择 **【休眠所有非活动标签页】** 强制回收。

### 3.3 深度原理问答

- **问：为什么调完虚拟内存后，多开 IDE 物理内存也只占 80% 出头？**
  - **答**：系统开机即拥有 55GB+ 提交配额和预分配连续 32GB 空间，内存管理器（Memory Manager）由“紧绷”变为“从容”。当打开新 IDE 时，系统毫秒级将后台闲置软件的冷工作集裁剪（Working Set Trim）并置换进预留的 Pagefile 中，零延迟把物理内存让给前台。
- **问：为什么 Chrome 自带的“省内存模式”感觉用处不大，启动依然 5GB？**
  - **答**：原生省内存策略极其保守。开机恢复上次标签时，它会并发拉起所有网页进程并渲染；且抖音、音乐、大模型长连接会被打上“不可丢弃”标记。Auto Tab Discard 直接调用底层 API 剥离渲染树与 JS 堆，只保留轻量元数据，所以能瞬间从 5G 压降到 2G。
- **问：虚拟内存继续调大到 64GB 或更大，会更好吗？**
  - **答**：**不会**。边际效益递减，32GB~48GB 是黄金甜点位。开满重度工具 Commit 才用了 ~32GB，后面闲置 23GB+。盲目再大不仅无法让电脑更快，反而白白浪费宝贵的 SSD 存储与写入寿命。
- **问：刚开机开齐软件风扇为什么变响？**
  - **答**：开机后 40 分钟内是软件集中唤醒期：Zed/VSCode 密集扫描项目索引、杀毒扫描、AMD 处理器激进睿频冲刺 5.0GHz+ 引发瞬时温升。虚拟内存属于存储冷文件，完全不发热，几分钟后负载下降风扇即自动安静。

## 实战案例（2026-10-03 ~ 10-05 本机压测与闭环）

- **底座加固实测**：通过 `sysdm.cpl` 锁定虚拟内存 32GB（初始 32768MB / 最大 49152MB），总 Commit Limit 达 55.2GB+。
  - 并发压测：同时拉起 **Zed (13 进程) + Cursor + VS Code + Chrome (数十标签) + Vibe助手 (6.3GB) + DeepSeek Harness**；
  - 铁证数据：总提交负载达 **31.90 GB**，`Pagefile PeakUsage: 2.4 GB` 平稳换页，**物理内存稳定在 81.1%~81.9%**，空闲留有 4.2GB 缓冲，彻底杜绝死机与闪退！
- **Chrome 内存黑洞实测**：
  - 初始痛点：Chrome 每次重启拉起会话，后台 5 个抖音等标签吃掉 2.8GB，整体飙升至 **5.1 GB**；
  - 处置验证：关闭预加载网页，配置 Auto Tab Discard 开机全休眠与一键裁决；
  - 铁证数据：执行标签休眠后，Chrome 内存**瞬间从 5.1GB 暴降至 2.0GB**（立省 3GB+ 物理内存），标签点击时毫秒级无缝重载。

## 踩坑备忘

- **必须点击【设置(S)】按钮**：在虚拟内存设置界面输入数字后，如果不点击右侧“设置(S)”直接点确定，修改将完全不生效且无任何报错提示。
- **严禁完全关闭虚拟内存**：即使物理内存 64GB+ 也绝不可关闭虚拟内存，许多大型软件和 Windows 核心组件依赖 Pagefile 预留 Commit 空间，关闭极易引发随机崩溃。
- **虚拟内存必须置于高速 NVMe SSD**：机械硬盘做虚拟内存会导致严重系统假死；高速 NVMe SSD 能把换页延迟控制在平滑感知范围。
- **Auto Tab Discard 慎选“打开临时空白页面”**：开启该项会导致点击休眠标签时先跳到扩展空白页再刷新，体验割裂；取消勾选后保持原 URL 就地重新加载，体验最佳。
