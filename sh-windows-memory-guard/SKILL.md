# sh-windows-memory-guard — Windows 内存过载防护与虚拟内存调优

针对“多开开发工具(Zed/VSCode/Cursor)、大模型、高负荷任务导致内存飙升（90%+），担忧电脑超内存死机或蓝屏”。
核心原则：**用高速 NVMe SSD 虚拟内存构筑兜底防线，以平滑的后台 I/O 换页替代系统死机与 OOM 闪退**。

## 四条核心认知（先读这个）

1. **物理内存占满 90%+ 绝不会直接死机或蓝屏**。Windows 拥有成熟的分页机制，物理内存吃满后系统会自动将冷数据转移至硬盘的 `pagefile.sys`。
2. **只有“提交配额（Commit Limit）”耗尽才会发生应用闪退**。物理内存 + 虚拟内存全部耗尽时，系统才会触发 OOM 保护机制强杀进程。只要手动将虚拟内存底座锁定在 32GB~48GB（总提交配额突破 55GB~70GB+），即可彻底杜绝死机与闪退。
3. **“卡顿”是安全代偿，非系统故障**。当数据在物理内存和固态硬盘之间置换时，SSD 相对物理内存的延迟差距会导致后台切前台时有 1~2 秒唤醒延迟。这是“用慢换不崩”的正常表现。
4. **虚拟内存置换不产生 CPU 高温，风扇狂转为伴生现象**。虚拟内存换页是存储 I/O，不引起 CPU 发热；开机 40 分钟内风扇狂转源于软件重启后的集中初始化（IDE 索引重建、杀毒扫描、AMD CPU 激进睿频），属正常瞬态。

## 工作流

1. 只读体检（`memory-triage.ps1` 输出物理内存、提交配额、页面文件大小及峰值使用）
2. 压力判型（区分是正常高负荷换页、虚拟内存不足，还是个别进程泄漏）
3. 防护加固（通过 `sysdm.cpl` 手动锁定 32GB~48GB 护城河）
4. 调优决策与答疑（调优上限边界、系统默认妥协原因、风扇噪音排查）
5. 验证与汇报

## Step 1 只读体检

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File <skill目录>\scripts\memory-triage.ps1
```

输出项及诊断重点：
- **物理内存占用率**：超过 85% 触发冷页置换（只要可用物理内存留有 2G~4G 缓冲即属健康）；
- **已提交 (Committed) vs 总配额 (Commit Limit)**：若 Committed 超过 Commit Limit 的 85%，说明提交池亟需扩容；
- **页面文件峰值 (Pagefile PeakUsage)**：大于 1GB 说明系统正平稳利用虚拟内存安全代偿，非系统故障。

## Step 2 压力判型表

| 现象与指标 | 关键数据特征 | 诊断判型 | 处置方向 |
|---|---|---|---|
| 物理内存 80%~90%，Commit 裕量 >20GB | 页面文件使用 >1GB，SSD 空间充足 | 黄金代偿态 | 系统正通过虚拟内存平稳兜底，绝不会死机；无需恐慌，放心使用 |
| 物理内存 >90%，Commit 裕量 <8GB | 提交已占用 >85% | 接近 OOM 警戒线 | **立即扩容虚拟内存**，防止下一次突发申请导致应用闪退 |
| 单个应用异常庞大 | 单 PID 独占 6GB+ 且持续膨胀 | 进程内存泄漏 | 检查是否为后台 LSP/调试器/前端构建工具泄漏，重启该服务 |
| 刚开机软件齐开，风扇狂转 | CPU 瞬时 30%~50%，磁盘 I/O 平稳 | 启动期密集计算 | Zed 正在建代码索引、杀毒全盘扫描、AMD 睿频温升；静候 5 分钟自动平息 |

## Step 3 处置与调优 SOP

### 3.1 虚拟内存加固配置（防死机核心步骤）

让系统不再受制于动态分配的瞬时延迟，直接开辟大容量安全气囊：

1. 按 `Win + R` 键，输入 `sysdm.cpl` 回车，打开“系统属性”。
2. 点击 **“高级”** 标签页 ➔ “性能”分组框内的 **“设置(S)...”**。
3. 在性能选项中，再次点击 **“高级”** 标签页 ➔ “虚拟内存”分组框内的 **“更改(C)...”**。
4. **取消勾选**最上方的 *“自动管理所有驱动器的分页文件大小”*。
5. 选中剩余空间充足的高速 SSD 盘符（首选系统 C 盘，空闲建议 >40GB）：
   - 单选 **“自定义大小”**：
   - **初始大小 (MB)**：填写 `32768`（即 32 GB）
   - **最大值 (MB)**：填写 `49152`（即 48 GB）
6. ⚠️ **关键操作**：**必须点击右侧的【设置(S)】按钮**，确认上方列表出现数值变更！
7. 点击【确定】依次关闭窗口，根据系统提示**重启电脑**生效。

### 3.2 调优决策与深度原理问答

- **问：为什么调完后，即便多开几个 IDE 物理内存也只占 80% 出头？**
  - **答**：系统开机即拥有 55GB+ 提交配额和预分配好的连续 32GB 空间，内存管理器（Memory Manager）由“紧绷”变为“从容”。当打开新 IDE 时，系统毫秒级将后台闲置软件的冷工作集剪裁（Working Set Trim）并置换进预留的 Pagefile 中，零延迟把高速物理内存让给前台。
- **问：为什么操作系统默认为什么不这么设？**
  - **答**：① 微软需兼顾 128G/256G 小硬盘电脑（若默认霸占 32G，普通用户 C 盘立刻爆满）；② 90% 普通用户仅轻度办公，根本用不满 12GB 提交；③ 只有开发者和多开重度用户才需要“用百 G 固态换取绝对稳定”。
- **问：继续调大到 64GB 或更大，会更好吗？**
  - **答**：**不会**。边际效益递减，32GB~48GB 是黄金甜点位。当前开满所有重度工具 Commit 才用了 ~32GB，后面闲置 23GB+ 裕量。盲目再大不仅无法让电脑更快，反而白白浪费宝贵的 SSD 存储与写入寿命。
- **问：刚开机开齐软件风扇为什么变响？**
  - **答**：开机后 40 分钟内是软件集中唤醒期：Zed/VSCode 密集扫描项目索引、杀毒扫描、AMD 锐龙处理器激进睿频冲刺 5.0GHz+ 引发瞬时温升。虚拟内存属于存储冷文件，完全不发热，几分钟后负载下降风扇即自动安静。

## 实战案例（2026-10-03 ~ 10-04 本机压测闭环）

- **初始痛点**：物理内存 23.2GB，`taskmon` 显示吃满 20.9GB（90.1%），进程数 511，后台 Pagefile 颠簸换页高达 16.7GB，系统随时面临卡死与 OOM 闪退。
- **处置方案**：通过 `sysdm.cpl` 将虚拟内存由动态托管设为固定 32GB（初始 32768MB / 最大 49152MB），总 Commit Limit 拉升至 55.2GB+。
- **压测与数据验证**：
  - 重启后配置即时生效（AllocatedBaseSize 32768 MB）；
  - **极限并发测试**：同时拉起 **Zed (13 进程) + Cursor + VS Code + Chrome (数十标签) + Vibe助手 (6.3GB) + DeepSeek Harness**；
  - **铁证数据**：总提交负荷达 **31.90 GB**（超出物理内存 8.7GB），`Pagefile PeakUsage: 2401 MB`（2.4GB）冷页毫秒级成功置换，**物理内存不仅未冲破 95%，反而平稳停留在 81.1%~81.9%**，物理可用空闲高达 4.2GB！

## 踩坑备忘

- **必须点击【设置(S)】按钮**：在虚拟内存设置界面输入数字后，如果不点击右侧“设置(S)”直接点确定，修改将完全不生效且无任何报错提示。
- **PowerShell 5.1 中文脚本必须保存为 UTF-8 BOM**：Windows 自带的 powershell.exe 对无 BOM 的 UTF-8 文件会按 ANSI 读取，导致中文输出乱码。
- **严禁完全关闭虚拟内存**：即使物理内存 64GB+ 也绝不可关闭虚拟内存，许多大型软件和 Windows 核心组件依赖 Pagefile 预留 Commit 空间，关闭极易引发随机崩溃。
- **虚拟内存必须置于高速 NVMe SSD**：机械硬盘做虚拟内存会导致严重系统假死；高速 NVMe SSD 能把换页延迟控制在可用范围。
