# Implement: 单切片独立会话推进（AFK 实现循环）

> **上下文纪律（Matt Pocock 核心反坑经验）**：  
> **一个切片一个会话，做完必须 `/clear`！**  
> 不要在同一个长会话里连着做多个切片——当上下文接近或超过 100k 时，注意力衰减呈平方级上升，这是 AI 代码越写越乱、胡言乱语的主因！  
> **人做两件（规划与 QA），Agent 做一件（实现）**：本技能就是 Agent 的全自动实现闭环。

---

## 一、实施准备：上下文与接缝确认

在动笔前，执行 3 项确定性确认：
1. **核对当前切片范围**：当前只做这 1 个 Ticket 的内容，严禁“顺便实现”其他切片的功能；
2. **确认测试接缝（The Seam）**：确认该切片在哪个预定公共接口处观察行为；
3. **查阅通用语言与 ADR**：读入 `CONTEXT.md` / `GLOSSARY.md` 与 ADR，保证代码中的命名与通用语言完全一致。

---

## 二、执行闭环：红-绿-重构标准流

强制调度 **[`tdd`](../tdd/README.md)** 规则执行推进：

```text
1. [红 Red]：在预定的 Seam 编写针对本切片验收条件的失败测试；
   ↳ 运行该单测，确保其准确地因为本切片功能缺失而挂掉（获取红灯信号）。
   
2. [绿 Green]：编写使该测试变绿的【最小实现代码】；
   ↳ 严禁过度设计，不写任何测试不需要的猜测性代码或提前抽象；
   ↳ 运行测试，确保切片核心断言变为绿灯。
   
3. [型 Typecheck]：执行编译或类型检查（tsc / mypy / cargo check / go build）；
   ↳ 严禁留下任何类型错误或隐式 any。
   
4. [整 Clean]：在绿灯保护下消除明显的坏味道（局部小重构）；
   ↳ 跑一次项目核心测试套件，确认既有功能未受破坏。
```

---

## 三、切片交付与硬门禁（Post-Implementation Gates）

切片代码完成后：
1. **生成清晰的代码变更摘要**（说明修改了哪些文件、覆盖了哪些接缝）；
2. **给出原子化的 Git 提交命令建议**；
3. **发出强制清空上下文提醒**：
   ```markdown
   ✅ Ticket [NN] 已在当前独立会话中完成实现并绿灯！
   
   ⚠️ 【关键工程纪律】：为了保持模型的最高智力区，请立即执行 `/clear` 清空当前会话！
   随后在干净的新会话中执行代码审查与人工 QA。
   ```

---

## 四、下游关联流转指引（Next Transitions）

- 👉 **必须先清空上下文（`/clear` 或开新会话）**；
- 👉 在清空后的会话中调入 **[`code-review`](../code-review/README.md)**，并行启动 Standards 轴与 Spec 轴进行客观双轴审查；
- 👉 审查无误后，**人类开发者必须亲自跑一遍（人工 QA）**，这是注入品味的唯一窗口；
- 👉 确认无误后，返回 **[`to-tickets`](../to-tickets/README.md)** 看板勾选该工单，挑选下一个 Frontier 切片。
