# sh-transcript-reader — 访谈转写稿与字幕转杂志风精读本

把碎片化的语音转写稿（`.srt` / `.txt`）或长视频访谈，转化为一份**高品质、去 AI 味、报刊出版物级、支持划词标注与全局跳转、支持自定义标签名、自解释语义命名的独立 HTML 沉浸式阅读单页**。

---

## 一、核心铁律：HTML 严谨语义命名规范（杜绝随意命名）

> ⚠️ **用户硬性红线**：HTML 文件名代表沉浸阅读资产，**严禁使用任何随意或临时哈希命名**！

### 1. 命名禁止项（Anti-Patterns）
- ❌ **严禁使用平台散列 ID 或视频哈希**：如 `douyin_7699461776018132258_reader.html`、`BV1xx411c7xx.html`；
- ❌ **严禁使用临时/默认空泛词**：如 `reader.html`、`output.html`、`test.html`、`temp_reader.html`；
- ❌ **严禁包含 Windows 非法文件字符**：如 `/ \ : * ? " < > |`；
- ❌ **严禁无意义的纯数字或机械后缀**：如 `12345.html`、`final_v2_new.html`。

### 2. 规范命名范式（Semantic Naming Formula）
所有生成的精读 HTML 文件必须遵循以下公式：

```text
标准格式：{清洗后真实标题}_精读本.html
多期系列：{YYYY-MM-DD}_{清洗后标题}_精读本.html
```

- **清洗规则**：
  1. 提取访谈的真实主标题（如《北大卷王，重新思考内卷与创造力》）；
  2. 符号安全映射：`|` 替换为 ` - `；`:` 替换为全角 `：`；`?` 替换为全角 `？`；`/` 与 `\` 替换为 `-`；引号一律剔除；
  3. 合并连续空白，标题长度安全截断在 50~60 字符内，结尾统一附带 `_精读本.html`；
  4. 最终范例：`北大卷王，重新思考内卷与创造力 - 钦文对话马兆远_精读本.html` 或 `北大卷王，重新思考内卷与创造力_精读本.html`。

## 二、双模态排版架构（Dialogue vs Monologue）

引擎具备智能上下文感知能力，支持自动识别或手动指定排版形态：

| 模态类型 | 适用内容场景 | 排版视觉表现 |
| :--- | :--- | :--- |
| **`dialogue` 访谈对话模式** | 双人播客、圆桌对谈、主持人问答 | 发言人徽章色彩绑定（松针绿嘉宾 vs 陶土赭石主持）、问答段落交替、时间戳对齐与双人发言人筛选器 |
| **`monologue` 演说论述模式** | 单人演讲、思想漫笔、劝学、口播、讲座 | **绝不出现生硬的假问答气泡**；自动归拢为思想流论述章节（Essay Sections）、论点小标题、连贯正文大段落与哲思金句拉花（Pull-quotes） |

## 三、去 AI 味设计与排版规范（对齐 sh-frontend-deai & sh-ui-layer-guide）

生成的 HTML 单页严格遵循以下视觉与交互基线：

1. **色彩哲学**：
   - **基底**：纸面柔和暖白 `#FBFBFA`（避免刺眼纯白，杜绝暗黑赛博终端风）；
   - **正文字体**：深邃松烟墨黑 `#1C221E`（避免粗糙纯黑 `#000`）；
   - **发言人语义绑定**：
     - 主讲嘉宾：学者松针深绿 `#1A4432` / 浅绿底 `#EBF3EE`；
     - 主持人/提问者：陶土赭石 `#8E4A28` / 暖褐底 `#FBF2EC`；
     - 重点引言：暖赭色 `#E68A36` 竖边强调；
   - **绝对禁止**：Tailwind 默认蓝紫渐变（`#6366F1` / `#8B5CF6`）、霓虹发光文字、无意义 emoji 装饰。
2. **文本版式**：
   - 标题：宋体/思源宋体衬线（`"Songti SC"`, `"Source Han Serif SC"`）；
   - 正文：舒适屏显无衬线体，阅读柱宽度受控在 `780px` 内，行高 `1.88`；
   - 关键金句提取为杂志大引言卡（Pull-quotes）。
3. **内容与交互架构（内置划词标注与全局跳转引擎）**：
   - **顶置导读面板**：4 组核心心智模型对比（如「赛道思维 vs 花园思维」）；
   - **分幕式章节（Thematic Acts）**：将零散字幕按逻辑演进划分为 5~7 个主题大幕；
   - **划词浮动标注工具条（Selection Popover）**：鼠标选中正文任意文字即浮现工具条，支持 **加粗（`B`）** 与 **4 色温润纸面荧光高亮**（琥珀黄 `#FBF0C4`、松针绿 `#DCF0E4`、陶土粉 `#F9E3D8`、青黛蓝 `#DDEBF4`），点击已有标记可随时改色、切换加粗，或一键「清空」该标记的全部样式；
   - **右侧常驻/可折叠全局标注抽屉（Annotation Drawer）**：
     - 宽屏展开时正文平滑左移让出空间，支持边看原文边看标注列表；
     - 支持按颜色/加粗筛选、一键复制全部标注为 Markdown 笔记，以及「清空全部」标注（5 秒内可撤销）；
     - **点击卡片跳转原文**：自动解除“仅看嘉宾/主持”筛选隐藏，平滑滚动至原文中央并触发 1.8 秒暖赭脉冲闪烁；单条移除配备 5 秒可撤销（Undo）轻提示条；
   - **自定义浏览器标签页标题（`🏷️ 改标签名`）**：仅修改 Chrome 标签栏显示的 `<title>`（不动正文 `<h1>` 主标题），便于多标签页分组辨识；刷新页面仍保留，支持一键恢复默认标题；
   - **双轨持久化（`localStorage` + 独立自包含 HTML 导出）**：标注与自定义标签名实时自动保存至浏览器 `localStorage`，并可通过顶部「💾 保存含标记 HTML」按钮将带标记与当前 `<title>` 的 DOM 导出/覆盖另存为自包含 HTML 文件。

## 四、标准执行 SOP

### 步骤 1：前置检查与输入获取
- **输入物**：已有 `.srt` 字幕文件、`.txt` 转写稿，或由 `sh-video-transcribe` / `sh-zhangshihao-douyin-dl` 刚生成的媒体及产物；
- **元信息提取**：确认访谈主标题、主讲嘉宾名、主持人名与时长。

### 步骤 2：自动渲染生成（单命令驱动）
使用本技能自带的脚本渲染引擎：

```powershell
# 脚本路径：
# D:\Users\language_projects\.agents\skills\sh-user-skills\sh-transcript-reader\scripts\render_reader.py

uv run "D:\Users\language_projects\.agents\skills\sh-user-skills\sh-transcript-reader\scripts\render_reader.py" `
  "<输入SRT或TXT文件路径>" `
  --title "<访谈真实标题>" `
  --guest "<嘉宾姓名>" `
  --host "<主持姓名>"
```

- 若未指定 `--title`，脚本将自动根据同名 summary 笔记或文件名提取；
- 脚本自动调用 OpenCC 将繁体字幕转为纯正简体中文，并自动修正常见 ASR 同音错字；
- 产物自动落在与媒体同目录下的 `{清洗后真实标题}_精读本.html`；
- 已生成的旧版精读本可直接**原地升级引擎**（仅替换/注入 CSS、UI 与 JS，不重跑字幕解析，也不改动正文与已有批注/页边注）：
  `uv run render_reader.py "<已有精读本.html>" --inject-only`；
- 若文件已含旧版标注引擎（无论早期外挂注入或模板内嵌版本），追加 `--force-inject` 先剥离旧 CSS/UI/JS 再注入新版，之后直接刷新浏览器标签页即可生效：
  `uv run render_reader.py "<已有精读本.html>" --inject-only --force-inject`；
- 标注引擎独立于 `scripts/annotation_engine.py`，渲染与注入共用同一份 CSS / UI / JS，重复注入自动跳过。

### 步骤 3：验收检查清单
- [ ] **文件名自检**：文件名是否严谨自解释（如 `北大卷王，重新思考内卷与创造力_精读本.html`），绝无 `douyin_*_reader.html` 等散列残渣；
- [ ] **编码检查**：文件头 3 字节绝无 BOM（`EF BB BF`），全篇纯正简体中文 UTF-8；
- [ ] **视觉与标注交互检查**：确认排版具备人文纸面质感，筛选器、字号切换、划词加粗/4色高亮、右侧抽屉跳转、「🏷️ 改标签名」（刷新保留与恢复默认）与「💾 保存含标记 HTML」功能正常，内嵌脚本通过 `node --check` 校验；
- [ ] **交付汇报**：给用户提供标准可点击的本地文件链接：`[标题_精读本.html](file:///D:/...)`。

## 五、内置划词标注与全局抽屉引擎（默认启用）

引擎真身：`scripts/annotation_engine.py`（零外部依赖，`file://` 离线直开可用），对外提供 `ANNOTATION_CSS`、`ANNOTATION_TOOLBAR_BUTTONS`、`ANNOTATION_OVERLAY_HTML`、`ANNOTATION_JS` 与幂等注入/剥离函数 `inject_annotation_engine(html)`、`strip_annotation_engine(html)`。

### 1. 交互契约
- **划词工具条**：`mouseup` / `keyup` 选中正文非空文本时，在选区上方浮现纸面质感工具条；支持加粗（`data-hl-bold`）与 4 色荧光（`data-hl-color`：`amber` / `jade` / `clay` / `mist`），点击已有 `.hl-mark` 可改色、切换加粗或移除；
- **标注抽屉**：顶部工具栏「📝 标注清单 (N)」开关；宽屏（`>=1280px`）展开时正文左移 `170px` 让出 `340px` 抽屉，窄屏为右侧滑出层；
- **清空与撤回**：工具条「清空」一次性移除当前标记的加粗与背景色；抽屉「清空全部」一次性移除全部 `.hl-mark`，两者均保留 5 秒「撤销（Undo）」轻提示条；
- **跳转**：点击抽屉卡片会自动切回「全文实录」解除 `.hidden`，`scrollIntoView` 平滑居中并施加 1.8 秒 `.hl-pulse`；
- **复制摘录**：抽屉内「复制 Markdown 摘录」按 DOM 顺序输出编号、加粗标记、发言人与时间戳；
- **自定义浏览器标签名**：顶部工具栏「🏷️ 改标签名」打开纸面弹窗，仅修改 `document.title` / `<title>`（正文 `<h1>` 不变），支持 `Enter` 保存、`Esc` 取消及「恢复默认」一键还原；已自定义时按钮高亮提示。

### 2. 持久化与导出
- **原始标题锚点与标注保护**：首次加载时将原始 `<title>` 锁存于 `<title data-orig-title="...">`；标注存储 key 始终为 `hl-annotations:<原始标题>`，修改标签名**不会**导致已有标注失效或丢失；刷新原始文件自动按「宿主段落索引 + 文本偏移」还原，已存在同位置标记时自动跳过，避免重复；
- **标签名热持久化**：自定义标签名写入 `localStorage`（key 为 `hl-tab-title:<原始标题>`），每次刷新或重新打开页面即刻自动应用到 Chrome 标签栏；
- **自包含导出**：顶部「💾 保存含标记 HTML」优先调用 `window.showSaveFilePicker`（可直接覆盖原文件或另存，非法文件名字符自动清洗为 `_`），不支持时回退为 `<当前标签名>_已标注.html` 浏览器下载；导出前清理浮动工具条、改名弹窗、脉冲类与抽屉展开态，保留全部 `.hl-mark`、当前自定义 `<title>`、`data-orig-title` 与引擎脚本，导出的文件可继续增删标注或改回默认标签名。

### 3. 验收断言
- 内嵌 `<script>` 块全部通过 `node --check`；
- 页面中 `id="hl-drawer"` / `id="hl-popover"` / `id="hl-drawer-toggle"` / `id="hl-rename-title"` / `id="hl-save-html"` / `id="hl-title-modal"` 各恰好 1 份；
- 选中正文后工具条出现；加粗 / 改色后 `.hl-mark` 与抽屉计数同步；改标签名后刷新页面 Chrome 标签名保持且原有标注完整还原；导出 HTML 内 `<span class="hl-mark` 数量与页面一致、`<title>` 与 `data-orig-title` 正确且无 BOM。

## 六、可选增强：侧栏注解版（Margin Notes，默认不启用）

**触发条件**：仅当用户明确点名「侧栏注解 / 页边注 / margin notes / 旁注 / 批注侧栏 / 注解版」，或要求「逐句解释这段转写」时启用。**默认精读本不加任何注解**，以免破坏纯读体验。

**适用场景**：语音自动转写稿常见同音误识、断句错位、口语冗余与繁体字残留（如「啟发」「交易→教育」「又注意→要注重」），直接读会卡。侧栏注解把「转写校订」与「语义注解」放到正文右侧页边距，**正文一字不改**。

**三条硬性版式契约**：
1. **正文优先**：正文列宽与位置必须与页面其他段落完全一致，侧栏是附属品，绝不能挤窄或左移正文；
2. **脱离排版流**：侧栏用「0 宽网格轨道 + 向页边距溢出 + sticky」实现，不占用正文宽度；
3. **一一对应**：正文只包 `<span>` 并把修正写进 `data-*`，每个编号与侧栏条目严格对应。

完整 CSS / JS / HTML 骨架、响应式阶梯、反模式与验收断言见：
`references/side-annotation.md`

**最小落地流程**：
1. 选定目标轮次（通常是嘉宾的一段长回答，ASR 噪声集中）；
2. 逐处标记并分类：`asr-mark`（转写校订）与 `gloss-mark`（语义注解）；
3. 由标记属性派生侧栏条目（序号连续，勿双份维护文案）；
4. 按参考文档末尾的断言自检，再交付。
