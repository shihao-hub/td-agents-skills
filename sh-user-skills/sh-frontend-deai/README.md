# 前端去 AI 味（sh-frontend-deai）

让 AI 生成的网页摆脱"一眼 AI"的千篇一律感。经典款 AI 味：蓝紫渐变、Hero 大标题+三卡片、Inter/Roboto 字体、Emoji 图标、空洞文案；蓝紫被骂多了之后又进化出新款：深黑底 + 高饱和霓虹多色 + 发光渐变描边 + Emoji 点缀的"高级感"皮肤——换了皮，仍是同一个模板。

根源认知：AI 味来自**求稳**——训练数据里 Tailwind 默认风格（蓝紫色 `#6366F1` / `#8B5CF6`）出现频率最高，AI 便把"现代网站 ≈ 蓝紫渐变"当成最不容易出错的答案。所以去 AI 味不是堆装饰，而是**主动偏离统计众数**：每个设计决策先问"最常见的默认做法是什么"，然后有理由地走另一条路。

图表/数据可视化页面的配色与图形规范不在本 skill 范围（另有 dataviz）；研发文档去 AI 味见 sh-tech-doc-writing。

## 接到前端任务的决策流程

### 第 0 步：识别默认陷阱

动工前先自检，任何一条命中都说明在走 AI 默认路线。注意：AI 味不是固定特征清单，是**统计众数**，而众数会迁移——清单会过时，"偏离当前默认输出"的原则不会。

经典款（1.0，蓝紫时代）：

- 配色：蓝紫/靛蓝渐变、Tailwind 默认色板直出
- 布局：Hero + 三个等宽卡片并排、完美居中对齐
- 字体：Inter / Roboto / system-ui 从头用到尾
- 文案："提升生产力""卓越的用户体验"式空话、Lorem Ipsum
- 组件：Shadcn / Material UI 默认样式零定制
- 动画：清一色 ease-in-out

新款（2.0，"高级感"时代）：

- 深黑/深蓝暗底 + 高饱和霓虹多色，到处发光
- 渐变细描边、彩色 text-shadow，颜色只做装饰不承载信息
- Emoji 点缀（⚡💡🚀）当氛围组、圆角徽章 pill 满天飞
- 对任何内容都套同一张"科技发布会"皮肤

### 第 1 步：风格从场景推导

先回答一个问题再谈任何视觉决策：**这个页面的内容是什么、给谁看、在什么场景用？** 风格从场景推导，不从"显得高级"推导。比视觉套路更深的一层 AI 味是场景错位：高中化学口诀做成深底霓虹赛博海报，每个元素单看都"精致"，合起来却是 AI 味——因为那张皮肤对任何内容都一个样。学生教辅就该长成笔记/手账的样子（该场景已有专门 skill：sh-edu-infographic，点名使用），内部工具就该克制安静，活动页才可以热闹。

场景想清楚后再定具体方向：

用户给了明确风格（参考网站、截图、品牌色）→ 严格照做：先提取参考对象的配色、字体、布局语言，再按该风格生成，不走上面的默认路线。

用户没指定时 → **不要默认蓝紫，也不要默认暗黑高级感**。按用户个人审美基线起步（见下），或给两个有特色的候选方向让用户挑。定方向时可借助配色工具（Coolors 按空格随机生成、Adobe Color 专业方案，见 references/resources.md），**定好后把具体色值写死在页面顶部注释里再开工**，避免生成中途漂回默认色。

#### 用户个人审美基线（未指定风格时的默认）

用户长期稳定的个人偏好，做用户自己的项目时默认按此起步：

- 浅色亮堂，不要暗色终端风
- 绿色主色调
- 圆角卡片
- 亲切感来自人的痕迹，不来自配色本身：手绘插画、手写体点缀、纸面质感比圆角更本质
- 反感装饰性 gimmick：无意义动效、炫技粒子

给第三方做的项目、或用户明确指定了其他风格时，以需求为准，基线只管"没说"的情况。

#### 颜色语义优先

颜色先承载信息，再谈好看。红=氧化、绿=还原、黄=重点这类语义绑定一旦建立就全篇一致，颜色承担了信息结构职责，装饰性滥用（到处发光、彩虹渐变）自然没有生存空间。定色值时不只问"主色是什么"，还要问"哪些颜色固定绑定什么含义"。

### 第 2 步：布局去套路

打破对称：不等宽分栏、错落排布、主次分明的视觉层级。Hero+三卡片是禁区，改用杂志式排版、左右分屏、大图+文字环绕等。敢于留白，而不是把每个格子填满。

### 第 3 步：字体有性格

避开 Inter/Roboto 单打独斗，标题与正文用不同字重的组合制造层级。中文场景可选思源黑体、霞鹜文楷等有性格的字体，代码感用等宽字体点缀。

### 第 4 步：图片系统

AI 生成的页面最常见的缺陷就是纯文字空壳，必须有图。按需取用（完整清单见 references/resources.md）：

- 功能图标：Iconify（iconify.design），统一 SVG 图标语言，禁用 Emoji
- 占位图：Picsum Photos（`picsum.photos/800/400`，URL 即图）
- 真实照片：Pexels（pexels.com）
- SVG 插画：unDraw（undraw.co，可改主色，改成站点主色后自然融入）

### 第 5 步：文案去空洞

写给具体的使用者，不写给投资人：

- 具体化："每天节省 2 小时重复劳动"，而非"提升生产力"
- 口语化："用起来就像呼吸一样自然"，而非"卓越的用户体验"
- 带情绪："再也不用在 10 个群里找文件了"，而非"高效协作"

### 第 6 步：组件库换血

需要组件库时优先有性格的小众库（8 选清单见 references/resources.md）：Aceternity UI（粒子/极光）、Magic UI（动画组件）、DaisyUI（30+ 主题）、Brutalist UI（粗野主义）等；Radix 这类无样式原语也是好路线——结构用它、皮自己画。用 Shadcn/MUI 也行，但必须深度定制。小众库 AI 容易记错用法，先查官方文档（或用 Context7）再写。

### 第 7 步：沉淀为项目规则

一次性页面走完上面即可；**会持续迭代的正式项目，把设计约束写成项目内 AGENTS.md**，让后续每次生成都自动带约束：

````markdown
# 项目设计规则

## 角色设定
你是一位资深独立设计师，追求每个像素都有温度，鄙视千篇一律的 SaaS 模板。

## 绝对禁止
- 配色：蓝紫/靛蓝渐变（#6366F1、#8B5CF6）、Tailwind 默认色板、纯平背景
- 布局：Hero+三卡片、完美居中对齐、等宽多栏
- 文案：空话、Lorem Ipsum、被动语态长句
- 组件：Emoji 当功能图标、默认组件样式零定制、动画清一色 ease-in-out

## 必须遵守
- 文案口语化，有数字、有场景、有情绪
- 图标用 Iconify，占位图用 Picsum，插画用 unDraw（按项目实际选型改）
- 配色：[本项目定死的具体色值]
````

## 参考真实网站（用户给了参考时的最高效路径）

- 给了网址：先读取该站，提取配色方案、字体选择、布局结构，再按该风格生成
- 只给了截图：结合截图与文字描述还原风格；也可用截图转代码工具（Screenshot to Code）拿到参考实现
- 什么都没给：从现成模板站（HTML5 UP、Start Bootstrap、Colorlib）找骨架起步，见 references/resources.md

## 进阶技巧：语境注入

先喂情绪，再出设计：给页面定一段情绪基调（书摘、电影桥段、一段用户独白），配色、布局、文案都往这种情绪上靠。例：《黑客与画家》选段 → 冷静理性 → 克制的留白、有序的网格、沉思专注的气质。情绪基调与用户审美基线打架时（比如语境要求暗黑风而用户偏好浅色），先问用户要哪个。

## 心法

AI 生成效果不理想，多数时候是指令不够明确——只说"做个好吃的"，厨师只能做最大众的家常菜。去 AI 味的本质是把"指挥官"的约束内化为生成时的默认纪律：**用户没说的地方，也要主动偏离统计众数；用户说了的地方，严格执行不走样。**
