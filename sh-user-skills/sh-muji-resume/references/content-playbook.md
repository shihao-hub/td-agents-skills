# 简历内容写作方法论（从高置信样本反推的通用骨架）

> 来源：2026-10-27 对一份高质量 3 年经验 Java/Agent 简历（飞书 wiki K3rPw1ijWi0OifkO7O5cqjNSnHh 转写样本）的结构化反推。
> 用途：AI 代写简历时按本骨架套内容；每条句式均有样本原句对应。配合 `../assets/ink-rule.css`（排版）与主 README（导出 SOP）使用。

## 一、信息架构骨架（固定顺序）

1. 头部：姓名 + 一行岗位定位（从工作经历岗位名提取）+ 联系方式左右栏（左：电话/邮箱，右：性别/年龄/到岗）。
2. 教育经历：一行搞定——`学校 - 专业 学历 全日制 | 起止年月`。
3. 个人优势：N 条有序列表（N ≈ 年限 × 2~3，3 年经验约 8 条）。每条一个能力域，不重复。
4. 工作经历：公司 | 职位 | 时间 一组左右栏 + 职责有序列表（4~6 条）。
5. 项目经历：每项目 = 左右栏（岗位 | 起止）+ 五节：**项目背景 → 技术架构 → 核心功能与技术攻坚 → 个人职责 → 项目成果**。
6. 全篇一条主线：选一个能贯穿所有项目的工程哲学（样本用的是"模型理解 + 工具查询 + 确定性执行 + 结果回查"的可信闭环），在优势/职责/攻坚中反复变奏。

## 二、可复用句式模板

| 场景 | 句式 | 样本原句 |
| :-- | :-- | :-- |
| 优势条 | 拥有N年以上X领域经验，先后参与A和B建设，具备"技能1＋技能2＋技能3"的复合能力 | "拥有3年以上滴滴核心出行业务研发经验……具备'Java微服务＋时空数据处理＋AI Agent工程化'的复合技术能力" |
| 职责条 | 负责/参与[模块]，围绕[业务对象]完成[技术动作A]、[B]及[C]等模块建设 | "负责上车点查询、空间索引、订单位置快照及上车点变更状态机等模块开发" |
| 攻坚条 | **[问题命名]**：[确定性做法]。针对[边界情况]，[机制]，[防呆规则] | "**时空意图结构化**：将用户表达拆分为……针对'明早送妈妈去医院'等模糊表达，Agent调用时间工具转换为确定时间，禁止模型直接生成时间戳" |
| 量化 | [指标]由约[X]降低至[Y]以内（带基线的降幅），禁用"提升X%"裸吹 | "上车点查询P99由约210毫秒降低至95毫秒以内" |
| 边界 | 模型负责[理解/生成]，[事实数据]通过工具查询，[高风险动作]由[确定性系统]执行 | "模型负责意图理解、参数补全和方案生成，地点、时间、路线、价格及供需信息通过工具查询，订单创建和取消由Java状态机执行" |
| 成果 | 平台支撑[规模]，[指标]达到[值]；[风险动作]100%经过[校验机制] | "订单创建、修改及取消全部经过结构化参数校验和用户确认" |

## 三、内容配比（单项目）

- 项目背景 1 段（100~150 字）：业务痛点 2~3 个 → 一句方案定位；
- 技术架构：分层列出（样本 9 层，每层"层名：组件、组件、组件"）；
- 核心攻坚 5~11 条：每条 = 问题命名 + 做法 + 边界处理 + 量化或防呆；
- 个人职责 5~6 条（只写"我做的"）；
- 项目成果 3~5 条（只写"平台做到的"，全量化）。

## 四、反模式清单（样本刻意避开的）

- ❌ 无基线量化（"效率提升 50%"没说从多少到多少）；
- ❌ 裸形容词（"精通""深入理解"无证据支撑）——样本的做法是"熟练掌握A、B和C微服务体系，**具备**领域建模、状态机、消息幂等……经验"（名词化证据链）；
- ❌ 模糊负责句（"负责XX项目的开发"）；
- ❌ 混淆平台成果与个人贡献；
- ❌ 用否定句式写成果（"未发生事故"单薄，样本仅在"零重复下单"这类安全叙事里保留否定式，且前缀了机制保证）。

## 五、LLM/Agent 简历专用模式（本样本最有价值的通用资产）

1. **幻觉治理叙事**：模型边界声明 + 工具查询事实 + Structured Output/JSON Schema 校验 + 用户二次确认 + 业务幂等 + 结果回查审计——六件套按订单/资金等高风险操作成套写。
2. **成本叙事**：成本感知模型路由（简单任务低延迟模型、复杂推理高能力模型，路由器综合任务类型/Prompt长度/历史成功率）。
3. **评测叙事**：角色模拟器生成坏例（地点缺失/时间冲突/供给不足/反复修改）、多维评测指标、未过回归门槛禁止上线。
4. **可观测叙事**：session_id 关联模型请求/工具调用/订单执行，支持按会话回放 Agent 决策过程。
5. **多类型回复器**：专业回复器/异常处理回复器/知识增强回复器分而治之——避免"单一大模型包打天下"的表述。

## 六、AI 代写工作流

1. 素材输入：让用户给原始经历（口头/文档/旧简历），按第一节骨架归位；
2. 每条产出先过第四节反模式清单，再对齐第二节句式；
3. 量化数据缺失时**占位并显式标记待用户确认**（如"【待补充：基线值】"），严禁编造数字；
4. 写完跑"面试追问预演"：每个数字问"怎么测的、基线是什么、多少样本"，答不上来的降级或删除；
5. 排版导出走本技能主 README 的 SOP。
