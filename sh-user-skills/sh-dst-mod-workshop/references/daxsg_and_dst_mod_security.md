# 饥荒联机版（DST）DaxSg 模组混淆壳工作机理与反逆向剖析

## 一、DaxSg 壳体系架构

DaxSg（国内模组圈常称“大仙三国/大仙壳”）是针对《饥荒联机版》Lua 模组的一种典型商业/防御型代码混淆加壳方案。其核心目标是防止模组开源逻辑被同行简单反编译或抄袭。

### 1. 目录结构特征
受 DaxSg 保护的模组呈现如下特征指纹：
* `modinfo.lua`：明文存储（由于 Klei 引擎在游戏启动时需直接解析元数据，作者通常保留明文）。
* `modmain.lua`：加壳引导器。压缩为单行代码，包含：
  - 自定义 Base64 字典字符解码器；
  - 混淆的常量表与控制流平坦化 VM 调度器；
  - 完整性自校验、路径探测与反调试触发器。
* `modmain0.lua` 与 `modmain1.lua`：密文载荷。
* `daxsg_mod_path.txt`：明文索引列表，记录所有被加密的业务脚本路径（如 `alicia`, `components/xxx` 等）。
* `scripts/*.lua`：被逐一处理为自定义字符集密文/二进制流的脚本文件。

## 二、反调试陷阱与自校验机制深度剖析

### 1. 反调试与沙盒感知（"Do not debug this file!"）
若逆向人员尝试使用独立 Lua 5.1 解析器脱机运行 `modmain.lua`，或引入了 `debug` 库进行函数 Hook，壳会触发防御分支：
* **现象**：脚本在根目录下尝试创建形如 `\s6qg..vbs`、`\sblg..vbs`（取拼音嘲讽简写）的文件，并在内部变量中注入 `"Do not debug this file!"` 报错或陷入死循环。
* **原因**：
  1. **环境检测**：壳在入口处检测宿主环境是否存在完整的 Klei 引擎全局变量（如 `TheSim`, `TheNet`, `KnownModIndex`, `GLOBAL.env` 等）；
  2. **路径校验**：校验 `MODROOT` 是否符合真实游戏工坊路径格式；
  3. **自校验（Self-Hash Check）**：壳会通过 `io.open(MODROOT .. "modmain.lua", "r")` 读取自身，若逆向者直接在 `modmain.lua` 开头或结尾插入了 Hook 代码，会导致哈希或长度比对失败，立刻引爆反调试分支。

## 三、通杀解密思路与落地方案

### 方案对比

| 解密方案 | 优势 | 劣势 | 推荐度 |
| :--- | :--- | :--- | :--- |
| **外部无侵入 Hook（modsettings.lua）** | **100% 绕过自校验与反调试**；由游戏官方引擎原汁原味触发完整解密流程；全自动批量 Dump 全部脚本 | 需依赖本地游戏运行环境 | ⭐⭐⭐⭐⭐ **最高推荐** |
| **独立 Lua 沙盒全真模拟** | 纯命令行免启动游戏 | 需 Mock 几十个 Klei 底层 C 导出对象与文件句柄，维护成本高 | ⭐⭐⭐ |
| **纯静态逆向还原 VM** | 彻底解耦运行环境 | DaxSg 每次版本更迭都会变换 VM 指令映射与常数加解密 Key，通用性较弱 | ⭐⭐ |

### 核心结论
**永远不要试图去“修改加密文件本身”来脱壳。**
最优雅、最彻底的破解思路是——**“让它自己解开，我们在最后一步摘取果实”**。
通过在游戏加载链的上游（`modsettings.lua` 或 `scripts/mods.lua`）劫持全局 `GLOBAL.loadstring`，模组的自校验完全感知不到任何异常，会在合法环境中将所有 `scripts/*.lua` 完整解密并送入 `loadstring`，此时一键捕获即可实现 100% 源码还原。
