# sh-agy-goal：目标达成模式（自治托管）

> 版本 v1.0.0 ｜ 移植自 Google Antigravity 斜杠命令 /goal，提示词提取自 language_server.exe（2026-09-23 构建）

## 功能介绍

Antigravity 的 /goal：官方释义 "Run until the specified goal is completely finished."。用户交代目标后 agent 进入闭环自治：执行 → 验证 → 发现问题 → 自行修复 → 再验证，反复迭代直到验收达标才停，适合托管长耗时任务（重构完整模块、整套测试跑通、批量修 Lint、"通宵运行"）。

原版机制（二进制提取）：

- 触发时注入：此任务旨在长时间无用户输入运行（如通宵）；务必极度彻底，只有确信目标完全达成才停止。
- 哨兵协议：全部完成输出 `<!-- GOAL_COMPLETE -->`；用户明确要求停止/取消输出 `<!-- GOAL_CANCELLED -->`。
- 系统强制续跑：模型想停但没打哨兵时，宿主注入审计提示词强制继续。

## 执行协议

### 1. 开工先立账

- 复述用户目标，列出**交付物清单**（每个显式需求/交付物一条），向用户确认后再动手。

### 2. 执行循环

- 做 → 验证（跑测试/构建/读产出文件）→ 发现问题 → 修 → 再验证。不许跳过验证宣布完成。
- 遇阻塞先自行排错至少一轮（换方法、查文档、最小复现），实在无法推进才求助，并说明已尝试什么。

### 3. 收尾强制自审计（核心）

每次想结束时先执行（原版审计提示词适配）：

1. 重读原始请求，识别每一个具体交付物。
2. 建 checklist，把每个显式需求/交付物映射到**具体证据**。
3. 逐项确认实际产出：文件内容、测试结果、构建日志等。
4. **"想做完"和"花过功夫"不等于做完了，只有真实证据算数。**
5. 有任何未完成或未验证项 → 继续干；有任何不确定 → 花更多时间验证。

### 4. 完成宣告

- 全部交付物有真实证据后，输出交付物→证据对照表，末尾打 `<!-- GOAL_COMPLETE -->`。
- 用户明确要求停止/取消 → 立即停，输出 `<!-- GOAL_CANCELLED -->` 和进度快照（已完成/未完成/如何接手）。

## 与原版的差异

- 原版由宿主检测停止并强制续跑；opencode 无此机制，靠上述自审计协议自律执行，哨兵保留作宣告。
