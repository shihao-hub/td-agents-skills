# Chapter 3: 基本工具（The Basic Tools）
## Core Idea
工具是双手的延伸：程序员应精通纯文本、shell、一种编辑器和源码控制等基础工具，并用文本操纵语言与代码生成器放大自己的能力，而不是被 GUI/IDE 的预设能力所限。

## Frameworks Introduced
- **Unix 哲学 / shell 管道**：提供做一件事情的锋利小工具，用管道组合成定制宏。适用时机：批量文件查询、过滤、转换、自动化常见任务。怎么做：学习 find/grep/xargs/sort 等，把常用命令序列固化为脚本。
- **调试方法论**：调试即问题解决，第一准则是不要恐慌。适用时机：面对任何 bug 报告。怎么做：可再现（最好一条命令）→ 使数据可视化 → 跟踪语句 → 橡皮鸭解释 → 二分/消除过程，直到找到根因而非症状。
- **代码生成器（被动 / 主动）**：被动生成器跑一次、产物成为独立源文件（模板、一次性转换）；主动生成器每次构建时从单一知识源重新生成（如由 DB schema 生成访问代码），是 DRY 原则的必需品。怎么做：保持输入格式简单，生成逻辑常只是 print 语句；把主动生成纳入构建。

## Key Concepts
- **纯文本**：人可读、自描述的知识格式；不过时、可被所有工具加工、易于测试，是异构系统间的公共最小公分母。
- **人可读 vs 人可理解**：能解析出字符 ≠ 能识别含义；带标签的格式（如 `<SSNO>`）才能部分解析。
- **源码控制（SCCS）**：项目级的时间机器与巨大的 UNDO 键；支持分支合并、审计、可重复构建。
- **橡皮鸭调试法**：向他人（或玩偶）逐步解释代码，被迫显式陈述想当然的假定，问题常自己跳出来。
- **坏变量邻居检查**：出错的变量值往往是被邻近内存覆写的；查看周边内存常给出线索。
- **WYSIWYAG**（所见即全部所得）：GUI 受限于设计者提供的能力，无法超越其模型。
- **编辑器精通**：可配置、可扩展、可编程；键击成为本能，编辑器成为双手的延伸。
- **跟踪（tracing）**：以规范格式打印诊断消息，观察随时间变化的状态，对并发/事件系统尤其有效。

## Mental Models
- 当需要在 GUI 里点十几步才能完成的临时任务时，用一条 shell 管道。
- 当看到"那不可能"的 bug 时，用"不要假定，要证明"——用这些数据、这些边界条件证明每个可信的"事实"。
- 当发现反复手写同样的东西时，用"编写能编写代码的代码"——做夹具（生成器）。

## Anti-patterns
- **见蹄印想斑马**：优先怀疑 OS/编译器/第三方库。失败原因：bug 几乎总在自己的应用代码里，浪费数周（"select 没有问题"）。
- **只修症状不修根因**：实际故障往往离观察点几步远。
- **对巧合进行调试**：不精确再现就动手改，易被巧合误导。
- **把 GUI 当万能工具**：无法自动化、无法组合工具，效率天花板由设计者决定。

## Key Takeaways
1. 配置、文档、数据尽量用纯文本并纳入源码控制——即使是一个人的项目。
2. 每换一个环境，先花时间精通该环境可带的 shell 和一种编辑器（统一键绑定）。
3. 调试前先让 bug 以最短步骤可再现；修完追问"为什么测试没抓住它"。
4. 吃惊程度与你对代码的信心成正比：吃惊时，重新验证你"确信"的每个事实。
5. 掌握一种文本操纵语言（Perl/Python/awk 等），把小时级的手工活缩到分钟。
6. 让两种环境（数据库 × 语言、语言 × 语言）共享知识时，写主动代码生成器并纳入构建，而不是手工双份维护。
