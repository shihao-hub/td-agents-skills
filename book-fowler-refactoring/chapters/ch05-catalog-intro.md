# Chapter 5: 介绍重构名录（Introducing the Catalog）

## Core Idea
本书余下部分是一份重构手法名录，每条手法用统一格式记录（名称、速写、动机、做法、范例），让重构既可查阅又可安全执行。名录不是巨细靡遗的清单，而是 Fowler 认为最常用、最值得命名的一组手法。

## Frameworks Introduced
**重构的记录格式（5 个组成部分）：**
1. **名称（name）**——建立重构词汇表的核心；同一手法常有多个名字，会列出常见别名（如"曾用名"）。
2. **速写（sketch）**——用简短的 before/after 代码转变帮你快速辨认和回忆手法；不是用来教学，初次接触应先读范例。
3. **动机（motivation）**——回答"为什么需要做这个重构"以及"什么情况下不该做"。
4. **做法（mechanics）**——一步步的简明操作笔记，源自作者的个人笔记，尽量把每步拆得极小（"婴儿学步"），每步之后测试；同时充当特殊情况的检查清单。
5. **范例（examples）**——用极简例子说明手法如何运作；刻意简化，一个范例通常只服务一项重构，保持手法自成一体。

**挑选手法的方式（5.2）：**
- 收录标准：最常用、值得命名与详解——或能提高整体重构技能，或对代码设计质量提升显著。
- 未收录的原因：太小太简单（如移动语句，1 版未收、2 版改收）；很少使用；与其他手法高度相似。
- 每个重构逻辑上都有反向重构，但不是所有反向都值得单独成条（如封装变量的反向几乎不做）。

## Key Concepts
- 名称（name）与重构词汇表
- 速写（sketch）
- 动机（motivation）
- 做法（mechanics）/ 婴儿学步
- 范例（examples）
- 反向重构（inverse refactoring）

## Mental Models
- **名录即参考工具**：知道要做什么重构但忘了步骤时查"做法"；初次使用时读"范例"。两部分的读者场景不同。
- **小步前进**：书中步骤刻意拆到极小并在每步后测试；实际工作中可以迈稍大的步子，但一旦出问题就回退并换更小的步子——情况越复杂，步子越小。
- **词汇表的力量**：给手法命名让"重构"成为可精确交流、可检索的单元，这是名录存在的根本理由。

## Anti-patterns
- 把速写当作教学材料或把"做法"当作完整教程来读——它们各有定位。
- 一步到位做大改动而不测试；出问题后不回退、不缩小步子硬扛。
- 期望名录巨细靡遗、包罗所有手法（包括所有反向重构）。

## Key Takeaways
- 每条重构按"名称—速写—动机—做法—范例"五段式阅读，按需取用：老手查速写和做法，新手读动机和范例。
- "做法"强调极小步长 + 每步测试 + 编译期检查；出问题就回退改用更小步骤。
- 范例是刻意简化的教科书，代码常还残留其他坏味道——那是给别的手法留的练习。
- 名录是有取舍的：只收最常用、最值得命名的手法；反向重构未必成条。
- 读后续章节时，遇到具体手法先看动机判断"该不该做"，再看做法决定"怎么做"。
