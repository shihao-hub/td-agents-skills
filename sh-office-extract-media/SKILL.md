# Office 文档内嵌原图提取

## 版本信息

| 项 | 值 |
|---|---|
| 版本 | v1.0.0 |
| 创建 | 2026-09-02 |
| 来源 | 一张知乎回答截图（"docx/pptx 改后缀为 zip 取原图"）沉淀为可执行 SOP |

## 为什么值得沉淀

docx / pptx / xlsx 本质上就是 ZIP 压缩包（OOXML 标准），作者插入的图片原封不动
地存在包里，**没有经过二次压缩**。而"右键另存为"拿到的是浏览器/编辑器渲染后的
近似版本，截图更是把分辨率钉死在屏幕像素上。所以取原图的正确姿势是**拆包**，不是
复制画面。

三个附带好处：一次拿全（几十张图不用逐张点）、格式保真（EMF 矢量图、GIF 动图都能
原样取出）、可追溯（package 里的条目名就是作者的插入顺序）。

## 怎么选执行方式

| 场景 | 走哪条路 |
|---|---|
| 有文件路径、要批量或要清单 | 跑本 skill 的 `scripts/extract_media.py`，一次搞定并产出清单 |
| 文档里图片是**链接**进来的（`word/_rels` 里有 TargetMode="External"） | 包里没有图，脚本会把这些外部路径列出来，顺着路径去找原文件 |
| 用户想自己动手，或环境里没有 python | 把下面的"手工四步"讲给他，配包内路径表 |

## 手工四步（给用户看的版本）

1. **备份**：先把文档复制一份再动手。不要在原文件上改后缀——万一忘了改回来，
   Word 会报"文件已损坏"。
2. **改名**：副本后缀 `.docx`/`.pptx`/`.xlsx` 直接改成 `.zip`。
   看不到后缀就先在文件夹选项里勾"显示文件扩展名"（Win11：资源管理器 → 查看 →
   显示 → 文件扩展名）。
3. **解压**：像平常一样右键解压这个 zip（Win 自带解压、7-Zip、Bandizip 都行）。
4. **找图**：进里面的 `media` 目录，图片全在那儿，按插入顺序命名 `image1.png`、
   `image2.jpeg`……

## 包内路径表（图片在哪个目录）

| 文档类型 | 图片目录 | 其它有用的目录 |
|---|---|---|
| `.docx` / `.docm` | `word/media/` | `word/embeddings/`（内嵌的 Excel/Visio 对象） |
| `.pptx` / `.pptm` | `ppt/media/` | `ppt/slides/slide1.xml`（哪张图在哪一页）、`ppt/notesSlides/` |
| `.xlsx` / `.xlsm` | `xl/media/` | `xl/drawings/` |
| `.doc` / `.ppt` / `.xls`（旧版） | 无——不是 ZIP | 先用 Office/WPS 另存为 docx/pptx/xlsx |

`media` 里除了图片还可能躺着音频、视频（`media/audio1.mp3`），脚本按后缀只挑图片。

## 用脚本提取（推荐）

```powershell
# 先看：有多少张、多大、什么格式，不写盘
python <skill目录>\scripts\extract_media.py report.docx --list

# 单个文档
python <skill目录>\scripts\extract_media.py report.docx -o .\imgs

# 批量：目录下所有 docx/pptx/xlsx，跨文档去重，增量提取
python <skill目录>\scripts\extract_media.py .\作业 -o .\imgs --dedupe --skip-existing

# PPT 里的 EMF/WMF 矢量图顺手转 PNG（需 Pillow；失败会保留原矢量文件）
python <skill目录>\scripts\extract_media.py deck.pptx -o .\imgs --convert-vector
```

脚本行为：

- **源文档只读**，从不改写；图片落到 `输出根目录/<文档名>/` 下，文件名沿用包内
  `image1.png` 这类原始条目名
- 包里没有位图时不会只说"没找到"：会列出 `.rels` 里的外部图片链接
  （`TargetMode="External"` 的路径），或指明"只有形状/图表这类非位图对象"
- 打印每张图的 `宽x高` 和体积（尺寸靠读文件头，**不依赖 Pillow**），顺手暴露
  "文档里看着很大、实际只有 300px 宽"的坑
- 输出根目录写 `_manifest.tsv`（文档、文件名、尺寸、字节、sha1 前 12 位、包内条目、
  落地路径）和 `_report.json`（跳过/去重明细）
- 退出码：`0` 正常（含"0 张图"）、`2` 目标不存在或没找到文档

## 交付前把这几件事说清楚

- **张数对不对**：`word/media` 里的图未必都显示在正文里——作者删掉图后残留、模板
  自带的水印/logo 都会留下。数量多于肉眼所见时逐张核对，别把残留当正文配图交出去。
- **尺寸证伪**：如果用户抱怨"图糊"，先用脚本报的尺寸确认是原图就小，还是他之前
  拿到的是缩略图——这是"右键另存 vs 拆包"最直观的对比证据。
- **矢量图形**：EMF/WMF 是矢量，浏览器和多数看图软件不认。按用户用途决定是否
  `--convert-vector`；转 PNG 会丢矢量信息，别默认转。
- **别交付压缩过的版本**：用户要的是原图，不要顺手缩放或重编码；要压由他决定。

## 常见坑

- **在原文件上改后缀**：最危险的操作。Word 打开时会报损坏，甚至触发"修复"。永远
  在副本上做，或直接用脚本（脚本只读源文件）。
- **旧格式 `.doc`/`.ppt`/`.xls` 解压失败**：它们是最早期的二进制格式（OLE 复合
  文档），不是 ZIP。脚本会明确报"旧版二进制格式"，此时先让用户另存为新格式。
  反过来，`.docx` 解压失败也可能是**文件损坏或加密**——加密的 Office 文件外层是
  OLE 容器，需要先去掉密码另存。
- **一张图都没有**：脚本会区分两种真实原因——图片是链接进来的（列出 `.rels` 里
  `TargetMode="External"` 的外部路径，原件在包外），或文档里的"图"其实是形状、
  SmartArt、图表（XML 绘制，包里确实没有位图）。按脚本给的线索排查，不要反复重试解压。
- **WPS / 第三方工具生成的文件**：绝大多数同样遵循 OOXML，能正常拆包；如果解压出来
  的目录结构明显不同，直接把看到的结构报给用户。
- **PPT 里图片跨页复用**：同一张图在 `ppt/media` 只存一份，多页引用它。按"图片张数
  = 页数"预期核对会以为丢图。
- **控制台中文乱码**：PowerShell 5.1 的 GBK 控制台显示 Unicode 文件名可能乱码，这是
  显示问题，文件落地是对的；需要确认时用 `Get-ChildItem` 的 `Name` 属性核对。
- **不确定用户手上的文件在哪**：先问路径或去 `桌面 / 下载 / 微信文件夹` 找，别凭
  文档名猜路径反复试探。
