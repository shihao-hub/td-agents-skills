# 图片水印去除（PIL+numpy 修补管线）

## 版本信息

| 项 | 值 |
|---|---|
| 版本 | v1.0.0 |
| 创建 | 2026-09-20 |
| 来源 | 一次真实会话复盘：移除压在签名笔画上的半透明水印，3 版迭代踩坑后收敛 |

## 总原则

1. **数值说话，不靠目测**：图层结构（水印在背景上还是压在笔画上）、颜色值域、掩码是否命中，全部用像素采样确认。肉眼在缩略图上"看着是深色"经常是错的。
2. **每阶段留中间产物校验**：填充后、混合后各设探针点打印数值；跑完整管线再看终图猜哪错了，是最大的时间黑洞。
3. **改的不是原图**：原始文件只读，结果写新文件。

## 工作流

### Step 1 拿到图片文件

- 用户给了路径 → 直接读。
- opencode 会话里粘贴的图（消息里没有路径时）：贴图以 base64 data URL 存在
  `C:\Users\29580\.local\share\opencode\opencode.db` 的 `part` 表（`data` JSON 字段，`type=="file"`、`url` 以 `data:image` 开头）。用本 skill 的 `scripts/extract_last_paste.py` 提取最新一张：
  ```powershell
  python <skill目录>\scripts\extract_last_paste.py C:\...\Temp\opencode\pasted.png
  ```
- 都没有 → 如实告知没收到图，可查库确认后再回复用户，不要凭空猜文件。

### Step 2 看清水印构成

把水印所在角裁出、放大 2-3 倍保存成临时 png，用读图工具查看。确认三件事：

- 水印是**文字**、**印章**还是**图案**；有没有**半透明拖影/阴影**伴随
- 它压在什么上面：纯背景 / 线条图案 / 渐变纹理
- 用户说"去水印"时，画面上署名类的**设计元素**（如手写签名）默认保留——签名自带的灰色阴影属于画作，平台盖的章才是水印；归属拿不准就问一句

### Step 3 像素采样标定

在 ROI 内采样并打印（写小脚本，不要凭一次目测）：

- 背景值（多点，注意暖色偏移 r−b≈3~5）
- 水印灰值域（典型半透明灰：v≈185~225，中性 r≈g≈b）
- 被保护图案的笔画色（典型深绿笔画 RGB(16,44,42)）及其 AA 边缘范围
- 判定图层：找"绿染中间调"像素（g−r>8 且 50<v<170）——若笔画穿过水印处整体变灰变浅，说明水印膜**压在笔画上方**，背景填充会把笔画一起擦掉

### Step 4 选策略

| 情形 | 策略 |
|---|---|
| 水印只在纯背景/平缓底纹上 | 掩码（值域判定）+ 背景扩散填充 |
| 水印膜压在笔画/图案上 | 首选**角部重建**：保留笔画核心（v < 阈值，如 135），其余全用干净背景重建，再用深色邻域均值重铺 AA。比逆透明度解膜稳得多 |
| 水印下图案复杂、无法重建 | 逆 alpha 合成 true = bg + (obs − bg − D)/(1−α)，需精确标定 D 和 α，谨慎使用 |
| 平台水印 + 签名阴影纠缠 | 值域高度重叠时像素级不可分，直接问用户"阴影要不要一起清掉"，默认整体清除重建更干净 |

### Step 5 执行修补

直接用本 skill 的 `scripts/clean_corner.py`（内置了下面全部三条 bug 的修复）：

```powershell
python clean_corner.py --src in.png --dst out.png --roi x0,y0,x1,y1 `
  [--keep-below 135] [--warm-diff 3] [--src-above 230] [--seed 7]
```

- `--roi`：处理区域 x0,y0,x1,y1（Step 2/3 确定，四周留 4~6px 余量）
- 算法：干净暖背景像素为唯一源的 light-only 扩散填充 → 按背景粒度加噪 → 两环深色邻域 AA 重建
- 依赖仅 PIL + numpy；无 cv2 也能跑

### Step 6 验证三件套（缺一不可）

1. **垂直/水平剖面**：跨笔画取一条线，逐像素打印 原图值 → 结果值，确认"笔画保住、水印清零、背景平滑"
2. **杂色扫描**：统计 ROI 内 |r−g|>40 或 |b−g|>40 的像素数，并与**原图**同区域对比——与原图一致的杂色是画作本身笔触，不是引入的 bug
3. **视觉复查**：裁角放大保存后用读图工具亲眼看一遍，再看一次全图缩略确认无意外改动

## 三个血泪 bug（写代码时逐条对照）

1. **numpy 布尔数组相加 = 逻辑或，不是计数**。`mask邻域和 >= 2` 这种邻域计数必须先把 bool 转 int：
   `padi = np.pad(mask, 1).astype(np.int32)` 再求和。直接 `bool+bool` 得到的"计数"全 True/全 False，掩码会莫名变空或膨胀。
2. **`np.pad` 默认 `mode='edge'` 是错的——默认是补 0**。扩散/卷积类迭代若不显式 `mode="edge"`，零值会从 ROI 四边随迭代渗入内部，整片背景被染暗。所有 pad 必须显式写 mode。
3. **混合环的分母分子必须是同一集合**。AA 重建时对"深色邻域" blending，分子分母都要只算深色邻居：
   `darkavg = Σ(深色邻居颜色)/深色个数`。错写成"8 邻域总和 ÷ 深色个数"，dn=1 时商上 1700，clip 后变纯白，通道错配还会喷出红/品红杂点。

## 常见坑

- **没图硬做**：用户说"这张图"但消息里没有图也没有路径——先查会话库确认，再如实要图
- **目测图层**：缩略图上笔画"看着是深色"，实际已被膜抬到 v≈100~160，进填掩码区直接被擦掉。必须采样
- **跑完才验证**：三个 bug 各毁掉一版输出，都是靠中间探针而非终图定位的
- **控制台中文乱码**：PowerShell 5.1 GBK 控制台打印 Unicode 文件名是显示问题，文件本体是对的；需要确认时用 Python `repr()` 或 `glob` 核对
