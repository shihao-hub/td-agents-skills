# Grilling: 方案压力测试与设计概念无情审问

> **基本功法则（Brooks《设计的设计》）**：  
> AI 没做我想要的，根本原因是**“缺设计概念”**。Claude Code 等工具默认的 Plan 模式急着造计划，而 Grilling 强制先对齐“到底要造什么”。  
> 逼出所有边界与未决假设，直到达成完全共识（通常 40~60 问）。**目标不是产出计划，是产出“我俩想的是同一个东西”。**

---

## 一、核心机制：设计决策树与 Frontier

将需求建模为一棵 **设计决策树（Design Tree）**：每个决策会分叉出挂在其下的次级决策。
- **Frontier（前沿问题集合）**：前置条件已被解决、当前即可提问的所有决策点。
- **事实归 AI，决策归人类**：涉及代码库现状、文件内容、技术 API 等客观事实，AI 必须自行派生探测工具去查，**严禁向用户提问任何你可以自己查到的事实**；涉及业务取舍、架构走向、交互偏好等**决策**，必须抛给用户并附带推荐答案。

---

## 二、提问节奏：单问渐进模式（Single-Question Mode / 默认推荐）

为了降低用户的认知负荷，防止长篇大论信息过载，**默认优先采用单问渐进流**：
**一次只提一个问题，每题必须给出推荐答案，用户只做单选**：

```markdown
❓ **Q[序号] - <问题标题>**: 
<问题的背景、上下文与关键分歧说明>

- [A] 选项 A 说明
- [B] 选项 B 说明
- [C] 选项 C 说明

➡️ **推荐选择**：[A] - <推荐理由：为什么从软件工程、深模块与可维护性角度推荐该方案>
```

> 💡 **批次模式（Round Frontier Mode）备选**：当用户明确要求“一次性列出当前阶段的所有问题”时，可将当前 Frontier 的问题按 Q1, Q2... 编号一次性抛出，每题同样必须包含推荐选项。

---

## 三、审问结束条件与共识交付物

当 Frontier 为空（设计树的所有分支均已探索完毕，没有任何未决假设或含糊推测）时，审问正式结束。
此时，AI 必须输出 **《设计概念共识书》（Design Concept Summary）**：
1. **核心业务概念与最终目标**（一句话定调）；
2. **已确认的决断清单**（按决策顺序列出 A/B/C 的确认结果）；
3. **显式非目标（Explicit Non-Goals）**；
4. **用户确认门禁**：“请确认以上共识是否完全符合你的设想。确认后进入下一阶段。”

---

## 四、下游关联流转指引（Next Transitions）

审问完成并获得用户确认后，**绝不允许直接编写业务代码**！根据项目规模执行下一步：

- **若涉及全新业务名词、复杂核心实体或多模块概念**：  
  👉 下一步调用 **[`domain-modeling`](../domain-modeling/SKILL.md)**，将核心术语固化进 `CONTEXT.md` / `GLOSSARY.md` 与 ADR。
- **若概念清晰且术语已知，直接进入规范编写**：  
  👉 下一步调用 **[`to-spec`](../to-spec/SKILL.md)**，将共识直接合成为目的地规范文档，并严格界定测试接缝（Seams）。
- **若逻辑极其复杂、拿不准状态机手感**：  
  👉 下一步调用 **[`prototype`](../prototype/SKILL.md)**，编写一次性抛弃型原型先行验证。
